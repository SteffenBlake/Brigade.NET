# 05 Query API

Depends: 02, 04.

- [x] Define separate `IQueryBuilder` and `ICommandBuilder` contracts. `DbReader` read terminals accept only `IQueryBuilder`; `DbWriter` write terminals accept only `ICommandBuilder`. Both expose `Compile()` returning `CompiledSql`. Core supplies `QueryBuilder` and `CommandBuilder`; engine packages may expose specialized .NET 10 builders.
- [x] Keep read composition on `QueryBuilder` (`With`, `WithRecursive`, `Select`, `From`, joins, `Where`, grouping, ordering, set operations, scalar/existence). Keep INSERT, UPDATE, DELETE, stored procedures, and trusted custom write SQL on `CommandBuilder`. A query builder must not expose write fluent methods or implicitly convert to a command builder.
- [x] Build SQL from SQL-shaped fluent methods and `FormattableString` SQL fragments, including join fragments; do not mimic LINQ. Ordinary interpolated values become parameters. `CommandBuilder` may accept `IQueryBuilder` children for INSERT-from-SELECT and supported command subqueries.
- [x] Store fluent calls as structured clauses and render in dialect SQL order at `Compile()`, regardless of call order. `From().Select()`, `Select().From()`, and `Select().From().Select()` must produce the same SQL when given the same projection terms. Keep repeated terms in their own call order: `Select` appends projections, joins append joins, `Where` appends predicates with an explicit conjunction rule, and grouping/ordering append terms. Define cardinality and duplicate-call behavior for single-slot clauses such as `From`, paging, and write target; reject conflicting values instead of silently discarding them.
- [x] Assign parameter names during final SQL rendering, in emitted SQL order. Call order must not change parameter order when the resulting structured query is the same. Nested builders must render through the same compilation context after clause ordering is resolved.
- [x] Parse composite formatting correctly, including escaped braces, alignment, repeated arguments, and format strings. Reject unknown Mise formats instead of passing them to `ToString`.
- [x] Parameterize each ordinary interpolation. Compile nested query fragments into one `StringBuilder` and one monotonically increasing parameter counter, including repeated holes and reused child builders. Generate stable, collision-free names in final SQL and ordered specifications. Never splice a child's independently numbered SQL without rebasing its placeholders. Create ADO.NET parameters through the selected provider factory and represent `null` as `DBNull.Value` at binding.
- [x] Treat format `raw` as the only interpolation bypass. The Roslyn analyzer requires the interpolated expression to be a compile-time constant string. Runtime values, including ordinary string variables, cannot use `:raw`.
- [x] Define `CompiledSql` as the immutable output of both `Compile()` methods: SQL text, ordered parameter specifications, `CommandType`, timeout, and supported engine-neutral behavior flags. Compilation must allocate fresh state; compiling twice must not share mutable parameters or change either result. Retire or adapt the existing `MiseCommand` snapshot so there is one clear execution contract.
- [x] Support the common read surface: WITH and recursive WITH; SELECT/DISTINCT; FROM; generated aliases; supported joins; subqueries; WHERE; GROUP BY; HAVING; ORDER BY; paging through engine rendering; set operations; scalar/existence; and trusted custom read SQL. Support INSERT values/select, UPDATE, DELETE, stored procedures, and trusted custom write SQL on the command surface.
- [x] `InnerJoin`, `LeftJoin`, `RightJoin`, and `FullJoin` take a `FormattableString` fragment containing the target and `ON` predicate. A generated relationship constant can be included with `:raw`; ordinary interpolated values in the same fragment become parameters. Alias relationship constants rewrite source qualification. `CrossJoin` takes a `FormattableString` table or alias fragment, or a child builder, and emits no `ON` predicate. Do not require any fluent join argument to be a compile-time constant.
- [x] Add engine capability checks for fluent join operations.
- [x] Diagnose use of a join kind unsupported by the selected engine. Cross joins use table/alias fragments or child builders and do not use relationship predicates.
- [x] Fluent operations that contain a query accept `IQueryBuilder` children, including CTEs, recursive CTE anchor/recursive members, derived tables, correlated subqueries, existence checks, set operations, and INSERT-from-SELECT commands. Child query compilation must use the parent's parameter allocation scope.
- [x] Render recursive CTEs per engine. PostgreSQL, SQLite, MySQL, and MariaDB use `WITH RECURSIVE`; SQL Server uses its recursive CTE form and keeps `MAXRECURSION` in its engine builder.
- [x] Model repeated predicates/order terms and nested/set queries as structured fragments. Empty collections and list expansion need explicit APIs and documented SQL; they must not silently create invalid `IN ()` text.
- [x] Keep engine-only syntax and return/generated-value behavior in runtime engine builders. Engine builders may implement the matching query or command contract. Reject child builders from an incompatible engine during compilation, before execution.
- [x] Do not expose `IQueryable`, expression trees, entity tracking, or SQL inferred from arbitrary C# lambdas.

Tests:

- [x] Table-driven unit tests assert exact SQL, parameter order/name/value/type hints, and command type for every common operation across all engines.
- [x] Permutation tests call `Select` and `From` in both orders and interleave repeated `Select`, `Where`, join, grouping, and ordering calls. Assert identical compiled SQL and parameter order for equivalent queries, stable within-clause term order, correct dialect clause order, and clear errors for conflicting single-slot calls. Cover command clauses and nested queries too.
- [x] Safety tests cover quote characters, SQL comments, semicolons, malicious values, generated constants, user const strings, parameterized runtime values in joins, rejected non-const `:raw` expressions, nulls, repeated arguments, escaped braces, and nested parameter-name collisions. No diagnostic may reject a join argument merely because it is not constant.
- [x] Reuse tests compile the same child into multiple parents and multiple positions in one parent, then concurrently compile independent queries and commands without text or parameter mutation. Assert monotonically numbered names and exact values across every nesting level.
- [x] Join tests prove the same generated relationship constant works through `FormattableString` input with every supported join kind, runtime join values become ordered parameters, and source aliases rewrite the predicate. Cross-join tests prove no `ON` clause is emitted.
- [x] Dialect capability tests assert the diagnostic for unsupported joins and assert no SQL is emitted for the rejected operation.
- [x] Dialect tests cover recursive CTE rendering, paging, identifier quoting, parameter markers, stored-procedure command type, and every declared engine deviation.

Done: `IQueryBuilder` trees compose valid parameterized reads, joins, CTEs, recursive CTEs, and correlated subqueries; `ICommandBuilder` composes valid parameterized writes and may nest read queries. Both compile to fresh, collision-free `CompiledSql` snapshots for all five engines; only compile-time constant `:raw` values bypass parameter binding.
